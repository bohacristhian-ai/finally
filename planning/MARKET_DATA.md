# Market Data

Simulator parameters, symbol rules, and the Massive API contract for [`PLAN.md`](PLAN.md) §6. **This document is normative** for the details it covers.

Both implementations satisfy the same interface, so nothing downstream — price cache, SSE, frontend — knows which is active.

## The Interface

```python
class MarketDataSource(Protocol):
    async def fetch(self, tickers: set[str]) -> dict[str, float]:
        """Return the current price for each requested ticker.

        May return fewer keys than requested if a symbol is unavailable.
        Must not raise on an unknown symbol.
        """

    def try_immediate_price(self, ticker: str) -> float | None:
        """Price for a newly admitted ticker, without waiting for the next poll.

        Returns a price if the source can produce one synchronously, else None.
        Called on the trade path when a ticker is admitted to the tracked set.
        """
```

The single background loop (`PLAN.md` §6) calls `fetch()` with the tracked set, writes results into the cache, and broadcasts changed tickers. Selection happens once at startup: `MASSIVE_API_KEY` non-empty → `MassiveSource`, otherwise `SimulatorSource`.

`try_immediate_price()` is what makes trading an unwatched ticker possible (`PLAN.md` §6, *Admission on Trade*). It is the one place the two sources genuinely differ in observable behavior:

| Source | `try_immediate_price()` |
|---|---|
| `SimulatorSource` | Generates and returns the seed price synchronously — it needs no network, so it never returns `None` for a well-formed symbol |
| `MassiveSource` | Always returns `None`. A price requires a network round trip, and the trade path must not block on one; the caller converts `None` into the retry response |

`MassiveSource` deliberately does **not** issue an out-of-band request here. The free tier allows 5 calls/min in total, and letting the trade path spend from that budget would let a user with a fast finger starve the polling loop.

## Symbol Rules

Applies to `POST /api/watchlist` and to LLM-initiated additions — same code path.

| Rule | Value |
|---|---|
| Normalization | Trim whitespace, uppercase |
| Valid pattern | `^[A-Z]{1,5}$` |
| Watchlist cap | 50 tickers |
| Duplicate add | Idempotent 200, not 409 |

There is deliberately **no check that a symbol exists in the real world.** In simulator mode there is no universe to check against, and adding a network round-trip to validate symbols would make the simulator depend on the thing it exists to replace. An unknown-but-well-formed symbol gets a generated price series (below).

## Simulator

Default source. Runs in-process, no external dependencies.

### Price Model

Geometric Brownian motion driven by a **single market factor** rather than a sector taxonomy:

```
market_factor ~ N(mu_market * dt, sigma_market * sqrt(dt))

for each ticker:
    idiosyncratic ~ N(0, sigma_ticker * sqrt(dt))
    log_return    = beta * market_factor + idiosyncratic
    price        *= exp(log_return)
```

A one-factor model produces visually convincing correlated movement — everything drifts together on a market move, with individual names diverging — while handling arbitrary user-added tickers for free. A sector map would need maintaining and could never cover symbols the user invents.

| Parameter | Value |
|---|---|
| `dt` | 0.5s, expressed as a fraction of a trading year (`0.5 / (252 * 6.5 * 3600)`) |
| `mu_market` | 0.08 annualized |
| `sigma_market` | 0.18 annualized |
| `sigma_ticker` | Per-ticker, see seed table |
| `beta` | Per-ticker, see seed table; **1.0** for unknown symbols |

### Random Events

On each tick, each ticker has a **0.02% chance** of an event: an additional one-off move drawn uniformly from ±2–5%, applied as a multiplier. At a 500ms cadence across 10 tickers this fires roughly once every 40 seconds somewhere on the board — frequent enough to be dramatic, rare enough to look like news rather than noise.

### Seed Prices

`session_ref` is set to the seed price at startup, so session change % is measured from these values.

| Ticker | Seed | β | σ (annual) |
|---|---|---|---|
| AAPL | 190.00 | 1.10 | 0.26 |
| GOOGL | 175.00 | 1.15 | 0.29 |
| MSFT | 415.00 | 1.05 | 0.24 |
| AMZN | 185.00 | 1.25 | 0.32 |
| TSLA | 245.00 | 1.80 | 0.55 |
| NVDA | 120.00 | 1.70 | 0.50 |
| META | 500.00 | 1.30 | 0.35 |
| JPM | 205.00 | 0.90 | 0.22 |
| V | 280.00 | 0.80 | 0.19 |
| NFLX | 640.00 | 1.35 | 0.38 |

### Unknown Symbols

A well-formed symbol not in the table gets:

- Seed price: uniform random in `[20.00, 400.00]`, **deterministic per symbol** (seed the RNG from the ticker string) so the same symbol yields the same price across restarts within a session
- `beta`: 1.0
- `sigma_ticker`: 0.30 annualized

### History Backfill

At startup the ring buffer for each seeded ticker is filled with a **full 60-minute window** of synthetic points (`PLAN.md` §6) generated by running the model **backwards** from the seed price, so the main chart is populated on first open rather than empty. That is 7,200 points at the simulator's 500ms cadence; `GET /api/history/{ticker}` downsamples on read, so buffer depth does not drive response size.

Backfilled points carry timestamps preceding container start. A ticker added later — including one admitted by a trade (`PLAN.md` §6, *Admission on Trade*) — backfills the same way at the moment it enters the tracked set.

## Massive API

Used when `MASSIVE_API_KEY` is set and non-empty.

**Massive is Polygon.io, rebranded on 30 October 2025.** It is not a proxy or a wrapper — it is the same service under a new name. Per the rebrand announcement, existing endpoints, SDKs, and API keys continue to work unchanged, which is why the shapes below are Polygon's v2 snapshot API verbatim.

| | |
|---|---|
| Current base URL | `https://api.massive.com` |
| Legacy base URL | `https://api.polygon.io` — still supported in parallel "for an extended period" |
| Auth | API key. Polygon/Massive accepts both `Authorization: Bearer <key>` and `?apiKey=<key>`; prefer the header so keys stay out of logs |

> **Still unverified:** the exact response *field names* below were not confirmed against live documentation — only the base URL, auth, and endpoint continuity were. Check `massive.com/docs/stocks` before relying on them, and correct this file rather than letting the code and this document disagree.

### Request

```
GET https://api.massive.com/v2/snapshot/locale/us/markets/stocks/tickers?tickers=AAPL,GOOGL,MSFT
Authorization: Bearer ${MASSIVE_API_KEY}
```

Tickers are requested in a single comma-separated call rather than one call per symbol — the free tier allows 5 calls/min in total, so per-symbol polling would exhaust the budget with three tickers on the board.

### Response

```json
{
  "status": "OK",
  "tickers": [
    {
      "ticker": "AAPL",
      "lastTrade": { "p": 190.12, "t": 1754918400000 },
      "prevDay":   { "c": 189.40 }
    }
  ]
}
```

Parsing: `lastTrade.p` → price. `prevDay.c` → `session_ref` when available; otherwise the first observed price becomes `session_ref`, matching simulator behavior. A ticker absent from `tickers` is omitted from the return value, leaving its cached price untouched.

### Polling Interval

| Tier | Interval |
|---|---|
| Free (5 calls/min) | 15s |
| Paid | 2–15s, configurable |

The poll interval is independent of the SSE broadcast cadence. Because only changed prices are transmitted (`PLAN.md` §6), a 15s poll against a 500ms broadcast loop produces one SSE event per poll rather than 30 identical ones.

### Failure Handling

Market data failures must never take down the app:

- Non-200, timeout, or malformed body → log a warning, leave the cache unchanged, retry on the next interval
- Prices go stale rather than disappearing; the frontend continues rendering the last known values
- Repeated failures do **not** fall back to the simulator — silently swapping data sources would be worse than visibly stale prices

## Testing Notes

- The simulator must be **seedable** so unit tests get deterministic sequences
- GBM correctness: over many steps, realized drift and volatility should approximate the configured `mu` and `sigma` within tolerance
- Massive parsing is tested against **recorded fixture responses**, never a live API call
- Both sources are tested against the same interface conformance suite
